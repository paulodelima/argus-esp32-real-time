```c
static int inv_extra(const argus_ctx_t *c) {
    int i, j, same_age, same_missed;

    /* coerencia estado <-> numero de tracks */
    if (c->state == ARGUS_IDLE && c->n_tracks != 0) return 0;
    if (c->state == ARGUS_TRACKING && c->n_tracks <= 0) return 0;

    for (i = 0; i < ARGUS_MAX_TRACKS; i++) {
        /* active e booleano: o firmware so escreve 0 (init/finalize) ou 1 (nascimento) */
        if (c->tracks[i].active != 0 && c->tracks[i].active != 1) return 0;
        if (!c->tracks[i].active) continue;

        /* missed so cresce junto com age e nasce 0 com age 1 */
        if (c->tracks[i].missed > c->tracks[i].age - 1) return 0;

        /* no maximo MAX_DETS tracks nascem (ou casam) por frame */
        same_age = 0;
        same_missed = 0;
        for (j = 0; j < ARGUS_MAX_TRACKS; j++) {
            if (!c->tracks[j].active) continue;
            if (c->tracks[j].age == c->tracks[i].age) same_age++;
            if (c->tracks[j].missed == c->tracks[i].missed) same_missed++;
        }
        if (same_age > MAX_DETS) return 0;
        if (same_missed > MAX_DETS) return 0;
    }
    return 1;
}
```

O estado de partida do contraexemplo tem `active = -2147483648` e `active = 2`, valores que nenhuma execucao real produz. O harness conta os encerramentos (`finalized`) a partir de `active`, e com valores diferentes de 0/1 essa contagem diverge dos eventos realmente enfileirados, o que derruba P4. Por isso basta exigir `active ∈ {0,1}`; com `ev_count == 0` e `ev_dropped == 0` na partida, um frame enfileira no maximo 8 eventos e nunca descarta.

A nova restricao se preserva em um frame porque `argus_init` escreve 0 em todos os slots, `argus_update` so escreve 0 (por idade ou em `finalize`) ou 1 (nascimento), e nenhum outro codigo toca o campo. As demais clausulas sao as mesmas da versao anterior e nao foram alteradas.
