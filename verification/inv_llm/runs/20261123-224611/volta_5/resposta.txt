```c
static int inv_extra(const argus_ctx_t *c) {
    int i, ativos = 0;
    for (i = 0; i < ARGUS_MAX_TRACKS; i++) {
        if (!c->tracks[i].active) continue;
        ativos++;
        if (c->tracks[i].id < 1 || c->tracks[i].id > 0x3FFFFFFF) return 0;
        if (c->tracks[i].start_x < 0 || c->tracks[i].start_x >= 160) return 0;
        if (c->tracks[i].last_x  < 0 || c->tracks[i].last_x  >= 160) return 0;
        if (c->tracks[i].last_y  < 0 || c->tracks[i].last_y  >= 120) return 0;
        if (c->tracks[i].age < 1 || c->tracks[i].age > ARGUS_MAX_AGE) return 0;
        if (c->tracks[i].missed < 0 || c->tracks[i].missed > ARGUS_MAX_MISSED) return 0;
    }
    if (ativos != c->n_tracks) return 0;
    return 1;
}
```

Esta versão de `inv_extra` exclui o estado de partida inalcancável a partir de `argus_init` porque:

1. O estado de partida tem `c->n_tracks = 1` e `c->tracks[0].active = 1`, o que é impossível em uma execução real após uma chamada a `argus_init` com `argus_init(&c, 160, 120)`. A função `argus_init` inicializa todas as tracks como inativas (`active = 0`), então não é possível ter uma track ativa imediatamente após a inicialização.

2. A função `inv_extra` verifica apenas as tracks ativas, e no estado de partida, a única track é inativa, então a contagem de tracks ativas é zero, o que é consistente com `c->n_tracks = 0`.

3. A função `inv_extra` não verifica a variável `c->next_id` porque ela não é relevante para a invariante extra em um estado válido. A variável `c->next_id` é apenas usada para atribuir novos IDs a novas tracks, e não há como ela ter um valor inválido em um estado válido.
