```c
static int inv_extra(const argus_ctx_t *c) {
    int i, j;
    for (i = 0; i < ARGUS_MAX_TRACKS; i++) {
        int dist;
        if (c->tracks[i].active != 0 && c->tracks[i].active != 1) return 0;
        if (!c->tracks[i].active) continue;
        if (c->tracks[i].id < 1 || c->tracks[i].id > 0x3FFFFFFF) return 0;
        /* quantos ids foram emitidos depois deste track (modulo o wrap) */
        dist = c->next_id - c->tracks[i].id;
        if (dist <= 0) dist += 0x3FFFFFFF;
        if (dist < 1 || dist > c->tracks[i].age * MAX_DETS) return 0;
        for (j = i + 1; j < ARGUS_MAX_TRACKS; j++)
            if (c->tracks[j].active && c->tracks[j].id == c->tracks[i].id) return 0;
    }
    return 1;
}
```

O estado de partida do contraexemplo é inalcançável: ele tem um track ativo com `id == next_id` (`dist` daria 0x3FFFFFFF). A partir dele, o firmware recria no mesmo slot um track com o mesmo id 1, e o harness não enxerga a finalização que de fato enfileirou um evento.

A invariante se preserva em um frame por três motivos:
- **Track novo:** recebe `id = next_id` antigo e `age = 1`, e `next_id` avança de 1. Logo `dist = 1 ≤ 1*MAX_DETS`, e esse id difere de todos os existentes, que tinham `dist ≥ 1`.
- **Track sobrevivente:** sua `age` cresce de 1, enquanto `next_id` avança no máximo `MAX_DETS` (uma emissão por detecção nova). Assim `dist ≤ (age+1)*MAX_DETS` continua valendo.
- **Wrap de `next_id`:** como `age ≤ ARGUS_MAX_AGE = 60`, `dist` nunca chega perto de 0x3FFFFFFF. Por isso a aritmética módulo o wrap é exata e os ids continuam distintos.
