```c
static int inv_extra(const argus_ctx_t *c) {
    int i;
    for (i = 0; i < ARGUS_MAX_TRACKS; i++) {
        int diff;
        if (c->tracks[i].active != 0 && c->tracks[i].active != 1) return 0;
        if (!c->tracks[i].active) continue;
        if (c->tracks[i].last_y != c->frame_h / 2) return 0;
        /* id valido e "recente": next_id avancou no maximo MAX_DETS por frame de vida */
        if (c->tracks[i].id < 1 || c->tracks[i].id > 0x3FFFFFFF) return 0;
        diff = c->next_id - c->tracks[i].id;          /* sem overflow: ambos em [1,0x3FFFFFFF] */
        if (diff <= 0) diff += 0x3FFFFFFF;            /* volta de 0x3FFFFFFF para 1 */
        if (diff < 1 || diff > c->tracks[i].age * MAX_DETS) return 0;
    }
    return 1;
}
```

**Por que exclui o contraexemplo:** no estado de partida, um track ativo tem `id == next_id` (distancia 0) e o outro tem `id` negativo. Isso permitia que o slot fosse reaproveitado com o mesmo `id=1`, e o harness nao enxergava a finalizacao.

**Por que se preserva em um frame:**
- Um track recem-criado recebe o `next_id` corrente com `age=1`. Depois dele, `next_id` avanca no maximo `MAX_DETS` vezes no mesmo frame, entao `1 <= diff <= MAX_DETS`.
- Um track que sobrevive ganha `age+1`, e `next_id` avanca no maximo `MAX_DETS` (com a volta modular de 0x3FFFFFFF para 1). Assim `diff` cresce no maximo `MAX_DETS` e continua `<= age*MAX_DETS`.
- Como `age <= ARGUS_MAX_AGE`, `diff` fica muito abaixo de 0x3FFFFFFF, entao nunca da a volta ate 0. As condicoes sobre `active` e `last_y` vem do contrato do harness (y fixo).
