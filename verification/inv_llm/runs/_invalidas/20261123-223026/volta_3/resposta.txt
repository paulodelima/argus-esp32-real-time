```c
static int inv_extra(const argus_ctx_t *c) {
    int i, j, dist;
    for (i = 0; i < ARGUS_MAX_TRACKS; i++) {
        if (c->tracks[i].active != 0 && c->tracks[i].active != 1) return 0;
        if (!c->tracks[i].active) continue;
        if (c->tracks[i].id < 1 || c->tracks[i].id > 0x3FFFFFFF) return 0;
        if (c->tracks[i].age < 1 || c->tracks[i].age > ARGUS_MAX_AGE) return 0;
        /* distancia circular (ids em 1..0x3FFFFFFF) de id ate next_id */
        dist = c->next_id - c->tracks[i].id;
        if (dist <= 0) dist += 0x3FFFFFFF;
        if (dist < 1 || dist > 1 + (c->tracks[i].age - 1) * MAX_DETS) return 0;
        for (j = i + 1; j < ARGUS_MAX_TRACKS; j++)
            if (c->tracks[j].active == 1 && c->tracks[j].id == c->tracks[i].id)
                return 0;
    }
    return 1;
}
```

**Por que exclui o estado do contraexemplo.** O estado de partida tem dois defeitos que a invariante rejeita. Primeiro, `active=-2147483648`, quando o codigo so atribui 0 ou 1. Segundo, `id=1476788224 > 0x3FFFFFFF`, e um track ativo tem `id=1073741823 == next_id` (`dist=0`), de modo que o proximo track criado reutiliza um id vivo.

**Por que se preserva em um frame.**
- **Track novo:** nasce com `id = next_id` antigo e `age = 1`. Apos o avanco circular de `next_id`, fica com `dist = 1`.
- **Track sobrevivente:** a cada frame, `age` sobe 1 e `next_id` avanca no maximo `MAX_DETS` passos, pois sao criados no maximo `n_dets ≤ MAX_DETS` tracks. Assim, `dist ≤ 1 + (age-1)*MAX_DETS ≤ 60` continua valendo, sempre muito abaixo do modulo `0x3FFFFFFF`.
- **Ids distintos:** dist nunca chega a 0, entao `next_id` nunca coincide com um id vivo. Como no maximo um track nasce por frame, tracks com idades diferentes tem distancias diferentes e, portanto, ids diferentes. Alem disso, `active` so recebe 0 ou 1.
