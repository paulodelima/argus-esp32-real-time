```c
static int inv_extra(const argus_ctx_t *c) {
    int i;
    for (i = 0; i < ARGUS_MAX_TRACKS; i++)
        if (c->tracks[i].active != 0 && c->tracks[i].active != 1) return 0;
    return 1;
}
```

O estado de partida do contraexemplo tem `tracks[0].active = -2147483648`. Esse valor conta como ativo para o firmware, que testa `!active`, mas provavelmente não é contado como finalizado pelo harness (inferência: o harness não foi mostrado). Assim, o evento gerado ao encerrar esse track sai da contagem de P4, e esse estado é inalcançável porque `argus_init` só escreve 0 e `argus_update` só escreve 0 (finalização/idade) ou 1 (track novo) em `active`. Logo, se todos os `active` estão em {0,1} antes do frame, continuam em {0,1} depois, e nenhum outro código toca nesse campo.
