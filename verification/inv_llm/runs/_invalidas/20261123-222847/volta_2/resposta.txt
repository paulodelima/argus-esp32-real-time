```c
static int inv_extra(const argus_ctx_t *c) {
    int i, j;
    for (i = 0; i < ARGUS_MAX_TRACKS; i++) {
        int dist;
        if (c->tracks[i].active != 0 && c->tracks[i].active != 1) return 0;
        if (!c->tracks[i].active) continue;
        if (c->tracks[i].missed >= c->tracks[i].age) return 0;
        if (c->tracks[i].id < 1 || c->tracks[i].id > 0x3FFFFFFF) return 0;
        /* idade (em ids) do track: quantos ids next_id avancou desde a criacao */
        if (c->tracks[i].id < c->next_id)
            dist = c->next_id - c->tracks[i].id;
        else
            dist = c->next_id - c->tracks[i].id + 0x3FFFFFFF;
        if (dist < 1 || dist > c->tracks[i].age * MAX_DETS) return 0;
        for (j = i + 1; j < ARGUS_MAX_TRACKS; j++)
            if (c->tracks[j].active && c->tracks[j].id == c->tracks[i].id) return 0;
    }
    return 1;
}
```

O contraexemplo parte de um estado inalcançável. Nele, um track ativo tem `id == next_id` (1073741823). Quando esse track é finalizado e o slot é reaproveitado no mesmo frame, o novo track recebe o mesmo id, e o harness não enxerga a finalização.

A função se preserva em um frame pelos seguintes motivos:

- **Track novo:** um track criado recebe `id = next_id` e começa com `dist = 1` e `age = 1`.
- **Tracks existentes:** em cada frame, `age` sobe exatamente 1, enquanto `next_id` avança no máximo `MAX_DETS` (inclusive na volta de 0x3FFFFFFF para 1, já que a distância é calculada módulo o ciclo). Assim, `1 <= dist <= age*MAX_DETS` continua valendo.
- **Unicidade dos ids:** como `dist >= 1` implica `id != next_id`, o id atribuído nunca colide com um id ativo, e os ids continuam distintos (remoções não quebram nenhuma das condições).
