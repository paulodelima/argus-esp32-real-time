```c
static int inv_extra(const argus_ctx_t *c) {
    int i;
    for (i = 0; i < ARGUS_MAX_TRACKS; i++) {
        if (c->tracks[i].active != 0 && c->tracks[i].active != 1) return 0;
    }
    return 1;
}
```

O contraexemplo parte de um track com `active=-2147483648`, que é inalcançável. O firmware trata esse track como ativo (testa `!active`) e o finaliza, enfileirando um evento. A contagem `finalized` do harness, que presumivelmente compara `active` com 1, não registra essa finalização, e por isso P4 quebra. A restrição se preserva em um frame porque `argus_init`, `finalize`, o ramo de idade em `argus_update` e a criação de tracks só escrevem os valores literais 0 ou 1 em `active`, e nenhum outro código toca esse campo.
