```c
static int inv_extra(const argus_ctx_t *c) {
    int i, j;
    for (i = 0; i < ARGUS_MAX_TRACKS; i++) {
        int dist;
        if (c->tracks[i].active != 0 && c->tracks[i].active != 1) return 0;
        if (!c->tracks[i].active) continue;
        if (c->tracks[i].id < 1 || c->tracks[i].id > 0x3FFFFFFF) return 0;
        /* distancia circular de id ate next_id (ids em 1..0x3FFFFFFF) */
        dist = (c->next_id > c->tracks[i].id)
             ? c->next_id - c->tracks[i].id
             : c->next_id - c->tracks[i].id + 0x3FFFFFFF;
        if (dist < 1 || dist > c->tracks[i].age * MAX_DETS) return 0;
        for (j = i + 1; j < ARGUS_MAX_TRACKS; j++)
            if (c->tracks[j].active && c->tracks[j].id == c->tracks[i].id)
                return 0;
    }
    return 1;
}
```

O contraexemplo parte de `next_id=1` com um track ativo de `id=1`. O novo track criado no mesmo slot herda o mesmo id, e por isso o encerramento não é contabilizado; esse estado é inalcançável, porque todo id ativo já foi emitido e, portanto, está estritamente "atrás" de `next_id`. A propriedade se preserva em um frame porque um track nasce com `age=1` e `dist` entre 1 e `MAX_DETS`, e a cada frame `age` sobe 1 enquanto `next_id` avança no máximo `MAX_DETS`. Logo `1 <= dist <= age*MAX_DETS` continua valendo, e como `age <= 60` a volta circular de 0x3FFFFFFF nunca alcança um id ativo, o que mantém os ids distintos entre si e diferentes de `next_id`.
