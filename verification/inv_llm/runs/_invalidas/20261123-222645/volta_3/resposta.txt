```c
static int inv_extra(const argus_ctx_t *c) {
    int i;
    for (i = 0; i < ARGUS_MAX_TRACKS; i++) {
        int diff;
        if (c->tracks[i].active != 0 && c->tracks[i].active != 1) return 0;
        if (!c->tracks[i].active) continue;
        if (c->tracks[i].id < 1 || c->tracks[i].id > 0x3FFFFFFF) return 0;
        /* distancia ciclica (no anel 1..0x3FFFFFFF) de id ate next_id */
        diff = c->next_id - c->tracks[i].id;
        if (diff <= 0) diff += 0x3FFFFFFF;
        if (diff < 1 || diff > c->tracks[i].age * MAX_DETS) return 0;
    }
    return 1;
}
```

Esta versão exclui o estado de partida do contraexemplo. Nele, o track ativo tem `id=1` e `next_id=1`, logo `diff = 0x3FFFFFFF`, muito acima de `age*MAX_DETS`. É exatamente essa colisão que faz o novo track reaproveitar o `id` do track finalizado, que o harness então não conta como finalizado.

Por que se preserva em um frame:
- **Track recém-criado:** recebe `id = next_id` antigo, e depois `next_id` avança no máximo `MAX_DETS` vezes no mesmo frame. Assim, `1 <= diff <= MAX_DETS = 1*MAX_DETS` com `age = 1`.
- **Track que sobrevive:** `age` cresce exatamente 1 e `next_id` avança no máximo `MAX_DETS`. Logo `diff' <= diff + MAX_DETS <= (age+1)*MAX_DETS`.
- **Sem volta completa do anel:** como `age <= ARGUS_MAX_AGE = 60`, temos `diff <= 60*MAX_DETS`, muito menor que `0x3FFFFFFF`. Portanto `next_id` nunca reencontra o `id` de um track vivo, e cada `id` novo difere dos `id` ativos.
