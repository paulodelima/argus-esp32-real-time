```c
static int inv_extra(const argus_ctx_t *c) {
    int i, j;
    for (i = 0; i < ARGUS_MAX_TRACKS; i++) {
        int dist;
        if (c->tracks[i].active != 0 && c->tracks[i].active != 1) return 0;
        if (!c->tracks[i].active) continue;
        if (c->tracks[i].id < 1 || c->tracks[i].id > 0x3FFFFFFF) return 0;
        dist = c->next_id - c->tracks[i].id;          /* distancia ciclica */
        if (dist <= 0) dist += 0x3FFFFFFF;
        if (dist < 1 || dist > c->tracks[i].age * MAX_DETS) return 0;
        for (j = i + 1; j < ARGUS_MAX_TRACKS; j++)
            if (c->tracks[j].active && c->tracks[j].id == c->tracks[i].id) return 0;
    }
    return 1;
}
```

O estado de partida tem um track ativo com id=1 e next_id=1, ou seja, distancia ciclica 0. Isso e inalcancavel, porque o track recebe next_id e o contador avanca logo em seguida. Esse estado e o que faz o harness confundir o track novo (tambem id=1) com o antigo e perder a conta de finalizados em P4; a invariante o exclui.

A invariante se preserva num frame por tres motivos:
- Cada track ativo tem `age` incrementado em 1, e no maximo MAX_DETS tracks sao criados por frame. Assim, a distancia `next_id - id` cresce no maximo MAX_DETS enquanto o limite `age*MAX_DETS` cresce exatamente MAX_DETS.
- Um track novo nasce com age=1 e distancia entre 1 e MAX_DETS.
- O id novo e o next_id antigo. Todo track ativo pre-existente estava a distancia entre 1 e 60, muito menor que 0x3FFFFFFF, entao o id novo nunca colide e os ids continuam distintos, inclusive na volta de 0x3FFFFFFF para 1.
